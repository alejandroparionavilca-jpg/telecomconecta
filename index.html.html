¿Qué es open5Gcube? Cómo se Instala

Parte I: Teoría de open5Gcube

1. ¿Qué es open5Gcube?

open5Gcube es un framework modular de código abierto diseñado para construir y gestionar laboratorios de redes móviles. Integra múltiples proyectos de redes móviles de código abierto (2G, 4G y 5G) en un entorno de gestión unificado. Su propósito es facilitar experimentos reproducibles en investigación, pruebas y educación, permitiendo a los usuarios desplegar redes de acceso radio (RAN), redes centrales (CN) y componentes de soporte de manera personalizable y extensible.

El framework aborda un desafío fundamental en la investigación de redes móviles: la integración de componentes RAN y CN de código abierto con equipos de usuario (UE) del mundo real. Mientras que las soluciones comerciales son estables pero costosas y cerradas, las alternativas de código abierto ofrecen flexibilidad pero presentan una curva de aprendizaje pronunciada y problemas de compatibilidad. open5Gcube combina lo mejor de ambos mundos: la adaptabilidad del software de código abierto con la facilidad de uso necesaria para configuraciones experimentales.

2. Arquitectura y Componentes

2.1. Contenedores Docker y Docker Compose

open5Gcube utiliza contenedores Docker y Docker Compose para el despliegue aislado de servicios. Cada componente de la red móvil (funciones de red del núcleo 5G, gNodeB, UE, etc.) se ejecuta en su propio contenedor, lo que garantiza:

  • Aislamiento: Los servicios no interfieren entre sí.
  • Reproducibilidad: Las configuraciones son consistentes en diferentes entornos.
  • Portabilidad: El framework puede desplegarse en diversas plataformas de hardware.

La orquestación remota de contenedores se realiza mediante SSH y Docker-outside-of-Docker (DooD), lo que permite distribuir la carga de trabajo en múltiples hosts físicos.

2.2. Stacks de Red Pre-construidos

open5Gcube ofrece stacks de red pre-construidos que representan diferentes combinaciones tecnológicas. Por ejemplo, un stack puede combinar OpenAirInterface (OAI) como RAN con Open5GS como núcleo de red. Esta modularidad permite a los investigadores seleccionar y combinar diferentes implementaciones de código abierto según sus necesidades experimentales.

2.3. Componentes Principales Integrados

El framework integra los siguientes proyectos de código abierto:

Open5GS

Implementación de núcleo 5G (5GC) basada en especificaciones 3GPP. Incluye funciones como AMF (Access and Mobility Management Function), SMF (Session Management Function), UPF (User Plane Function), NRF (Network Repository Function), entre otras.

OpenAirInterface (OAI)

Plataforma de código abierto para RAN que implementa estaciones base (eNB/gNB) y equipos de usuario (UE).

UERANSIM

Simulador de UE y RAN para 5G. Emula el comportamiento de un equipo de usuario 5G en diversos escenarios de despliegue.

srsRAN

Suite de software de código abierto para RAN 4G y 5G, compatible con hardware SDR (Software Defined Radio).

osmocom

Conjunto de proyectos para redes móviles 2G y 3G.

pySim

Herramientas para la provisión de tarjetas SIM.

2.4. WebUI para Control y Monitoreo

open5Gcube incluye una interfaz web (WebUI) que permite el control visual y el monitoreo de los despliegues de los stacks. Sus casos de uso principales incluyen:

  • Configurar, iniciar y detener stacks específicos.
  • Visualizar el estado de salud de los contenedores en tiempo real.
  • Acceder a los logs de los servicios.
  • Gestionar la configuración de VoLTE basada en Open5GS + Kamailio IMS.

2.5. Soporte para Hardware SDR y Configuraciones Emuladas

open5Gcube soporta tanto hardware SDR físico (USRP X310/B210) como configuraciones emuladas. Esto permite a los estudiantes sin acceso a hardware costoso practicar con simulaciones, mientras que los investigadores pueden validar sus experimentos en entornos reales.

2.6. Redes Virtuales Docker

El framework utiliza tres redes virtuales Docker para gestionar la conectividad:

  • corenet: Red para la comunicación entre las funciones del núcleo de red. Utiliza macvlan para asignar direcciones IP directamente desde la red física, facilitando la integración con equipos externos.
  • rannet: Red para la comunicación entre la RAN y el núcleo.
  • uenet: Red para la comunicación de los equipos de usuario.

3. Flujo de Trabajo Típico

Un flujo de trabajo típico con open5Gcube sigue estos pasos:

  1. Preparación del entorno: Instalación de dependencias (Docker, Docker Compose, SSH) en el host o hosts.
  2. Clonación del repositorio: Obtención del código fuente desde GitHub.
  3. Configuración: Ajuste de variables de entorno en archivos .env para definir IPs, PLMN, bandas, etc.
  4. Construcción de imágenes: Ejecución de make build-cacher-start docker-build-all para construir todas las imágenes Docker de los subproyectos. Este proceso puede tardar varias horas.
  5. Despliegue del stack: Selección y despliegue de un stack pre-construido desde la WebUI o mediante línea de comandos.
  6. Verificación: Comprobación del estado de los contenedores y conectividad de los UEs.
  7. Experimentación: Realización de pruebas (ping, iperf3, captura de tráfico) y recolección de datos.

4. Relevancia para la Formación en Telecomunicaciones

open5Gcube es una herramienta pedagógica de gran valor para estudiantes de telecomunicaciones porque:

  • Democratiza el acceso: Permite experimentar con redes 5G sin necesidad de infraestructura costosa.
  • Integra múltiples tecnologías: Los estudiantes trabajan con RAN, núcleo y UE en un solo entorno.
  • Facilita la reproducibilidad: Los experimentos pueden replicarse y compararse.
  • Prepara para el mundo laboral: Las habilidades en Docker, orquestación de servicios y configuración de redes 5G son altamente demandadas.

Guía Completa de Instalación y Aplicación de open5Gcube

1. Introducción

open5Gcube es un framework modular de código abierto diseñado para construir y gestionar laboratorios de redes móviles. Integra proyectos de código abierto de redes 2G, 4G y 5G en un entorno de gestión unificado, permitiendo a investigadores, estudiantes y profesionales desplegar redes de acceso radio (RAN), redes centrales (CN) y componentes de soporte de manera personalizable y reproducible. El framework utiliza contenedores Docker para el aislamiento de servicios, stacks pre-construidos que combinan diferentes tecnologías (como OAI-RAN con Open5GS), y una interfaz web (WebUI) para el control visual y monitoreo de los despliegues.

2. Requisitos Previos

Fuente: Guía de configuración de plataforma para Open5GS + UERANSIM.

2.2. Configuración del BIOS

Para un rendimiento óptimo, se recomienda deshabilitar las siguientes funciones desde el BIOS:

  1. Hyper-Threading (Hyperthreading Disabled)
  2. C-States (C-State Disabled)
  3. Intel SpeedStep (Deshabilitado)
  4. CPU Frequency Control y P-States (deshabilitados)

Esto reduce la deriva de las frecuencias portadoras y mejora la estabilidad del sistema.

2.3. Sistema Operativo

Ubuntu 22.04 LTS es la distribución recomendada como host base. Se recomienda instalar el kernel de baja latencia para garantizar tiempos de respuesta predecibles en aplicaciones 5G:

sudo apt install linux-image-lowlatency linux-headers-lowlatency
sudo apt install linux-tools-lowlatency

3. Instalación Paso a Paso

3.1. Instalar Paquetes Requeridos

sudo apt update && sudo apt upgrade -y
sudo apt install -y linux-tools-common net-tools make git-lfs \
  ca-certificates curl gnupg openssh-server python3-virtualenv

Fuente: Repositorio oficial de open5Gcube.

3.2. Clonar el Repositorio

git clone https://github.com/open5Gcube/open5Gcube/
cd open5Gcube

3.3. Instalar Docker Engine

open5Gcube utiliza versiones fijas de Docker para garantizar la reproducibilidad. El script de instalación se encuentra en modules/base/docker/o5gc/install-docker.sh y se ejecuta con:

make system-install-docker

Fuente: Repositorio oficial de open5Gcube.

Después de la instalación, agrega tu usuario al grupo docker para evitar usar sudo:

sudo usermod -aG docker $USER

Cierra sesión y vuelve a iniciarla para que los cambios surtan efecto.

3.4. Instalar el Servicio de Inicio de open5Gcube

make systemd-install-unit

Este comando instala el servicio systemd que permite iniciar open5Gcube automáticamente al arrancar el sistema.

3.5. Construir las Imágenes Docker

Este paso es el más largo (puede tardar varias horas) y construye todas las imágenes Docker de los subproyectos integrados:

make build-cacher-start docker-build-all

Nota: Ten paciencia y toma un café. Este proceso compila todas las imágenes necesarias para los stacks de red.

3.6. Iniciar la WebUI

Una vez construidas las imágenes, inicia la interfaz web:

make webui-start

La WebUI se inicia automáticamente al arrancar el sistema y escucha en el puerto HTTP estándar (80). Accede a ella desde tu navegador en http://<IP_del_host>.

4. Configuración

La configuración de open5Gcube se realiza a través de archivos de entorno (.env) ubicados en el directorio etc/.

4.1. Archivo local.env (Configuración del Sistema)

Este archivo define parámetros específicos de la instalación:

ParámetroDescripciónValores posibles
CLOCK_SRCFuente de reloj para el USRPexternal o internal
CORENET_DRIVERDriver de red para el núcleomacvlan (múltiples hosts) o bridge (un solo host)
CORENET_MACVLAN_IFACEInterfaz padre para macvlanEj: eno1
USRP_IFACEInterfaz del adaptador 10G para USRP X310Ej: enp3s0f0
ENB_HOSTNAMEHostname del host RAN para eNBEj: o5gc2
GNB_HOSTNAMEHostname del host RAN para gNBEj: o5gc3

Ejemplo de configuración para un solo host:

CORENET_DRIVER=bridge
USRP_IFACE=enp3s0f0
ENB_HOSTNAME=localhost
GNB_HOSTNAME=localhost

4.2. Archivo settings.env (Configuración de Red Móvil)

Define parámetros de la red móvil como PLMN, TAC, APN y frecuencias:

# Mobile Network
MCC=001
MNC=01
TAC=1
APN=internet
# Network Slice Selection Assistance Information
NSSAI_SST=1
NSSAI_SD=ffffff
# 5G Band
NR_BAND=78
NR_ARFCN=641280

4.3. Archivo uedb.env (Base de Datos de Suscriptores)

Contiene las credenciales de las tarjetas SIM (IMSI, Key, OPc). Cada línea representa un suscriptor:

001010000052100 F18E5DB0A8B5B8A0304E9113D121DFE3 E83C9CF73E3B9E82E48005A696E86AD8
001010000052101 F18E5DB0A8B5B8A0304E9113D121DFE3 E83C9CF73E3B9E82E48005A696E86AD8 12345678

Fuente: Repositorio oficial de open5Gcube.

4.4. Archivo networks.env (Configuración de Redes Docker)

Define las subredes y direcciones IP estáticas de los contenedores. Normalmente no necesita modificarse.

5. Uso de open5Gcube

5.1. Comandos Principales (Makefile)

El Makefile es el punto de entrada central para todos los comandos. Todos los comandos comienzan con make:

# Ver todos los targets disponibles
make help
# Construir todas las imágenes Docker
make docker-build-all
# Construir una imagen individual (ejemplo: AMF de OAI)
make docker-build-oai-amf
# Eliminar todas las imágenes
make docker-purge-all-images

Fuente: Repositorio oficial de open5Gcube.

5.2. Ejecutar un Stack de Red

Para cada stack definido en el framework, existe un comando make run-. Por ejemplo, para ejecutar un stack 5G-SA compuesto por OAI-RAN y Open5GS:

make run-oairan-open5gs-5g

Para detener el stack, presiona Ctrl+C.

Iniciar componentes individualmente:

# Solo el núcleo de la red
make run-oairan-open5gs-5g-core
# Solo el gNodeB
make run-oairan-open5gs-5g-gnb

Fuente: Repositorio oficial de open5Gcube.

5.3. Monitoreo con ctop

Para una vista en tiempo real de los contenedores en ejecución:

make ctop

5.4. Interfaz Web (WebUI)

La WebUI proporciona una interfaz gráfica para:

  • Ver el estado de los contenedores: logs, salud, información detallada.
  • Iniciar y detener stacks: con opción de ajustar configuraciones.
  • Leer y escribir tarjetas SIM: mediante pySim.
  • Acceder a enlaces de servicios web: proporcionados por el stack.

Accede a la WebUI en http://<IP_del_host> (puerto 80 por defecto).

7. Solución de Problemas Comunes

ProblemaPosible CausaSolución
Alto uso de CPUFalta configurar Idle-PC en routers IOSAcceder a la configuración del router y ajustar Idle-PC
Los contenedores no inicianRAM insuficiente o imágenes no construidasVerificar docker ps -a y asegurar que make docker-build-all se completó
No se puede acceder a la WebUIPuerto 80 ocupado o servicio no iniciadoVerificar sudo systemctl status open5gcube-webui y liberar el puerto
Error de conexión SSH a hosts RANClaves SSH no configuradasEjecutar ssh-copy-id <hostname> desde el Controller
El UE no se registraCredenciales SIM incorrectasVerificar uedb.env y que el IMSI coincida con la configuración de UERANSIM

8. Buenas Prácticas

  1. Documenta tus configuraciones: Guarda los archivos .env personalizados en un repositorio separado para reproducibilidad.
  2. Usa el kernel de baja latencia: Esencial para experimentos de rendimiento en 5G.
  3. Monitorea los recursos: Utiliza ctop y docker stats para detectar cuellos de botella.
  4. Aprovecha la modularidad: Combina diferentes stacks (OAI + Open5GS, srsRAN + Free5GC) según tus necesidades experimentales.
  5. Realiza pruebas de compatibilidad: open5Gcube ha sido validado con múltiples smartphones comerciales (Samsung Galaxy S25, OnePlus 13, Google Pixel 9, iPhone 13 Mini, etc.).
